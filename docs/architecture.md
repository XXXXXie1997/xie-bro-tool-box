# 蟹小箱 · 平台与子应用架构

更新日期：2026-10-12

状态：已实现 0.1 平台开发预览。已实现与待实现的边界见下方进度，完整任务见根目录 todoList。

## 当前实现与选型

- 桌面：.NET 10 + WPF，首发 x64 目标；源码仍在根目录。Windows 10 22H2 与 Windows 11 是兼容目标，尚未完成独立测试机验收。
- 桌面生命周期：Windows NotifyIcon 托盘（仅此处引用 Windows Forms），关闭隐藏窗口，托盘恢复或明确退出；退出时等待模块任务取消。用户及数据目录范围的命名互斥量/激活事件防止重复实例，恢复由 WPF Dispatcher 执行。参考 [NotifyIcon 官方文档](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.notifyicon?view=windowsdesktop-10.0)。
- 后台：ASP.NET Core 10、Identity、EF Core、MySQL（目标 8.4）；使用 Oracle 官方 EF Core 驱动和 MySQL 初始迁移。数据库部署位置后续确定。
- 账号：用户名 + 密码统一登录 / 注册，已有用户名验证密码，新用户名直接创建账号并登录；密码 6–128 位，不强制字符组合。暂不接入邮箱或验证码，密码找回入口置灰。后续接入手机号验证和绑定，沿用同一 User ID。
- 会话：服务端保存高熵随机访问/刷新凭证的哈希，访问有效期 20 分钟、刷新有效期 7 天。刷新轮换、旧凭证重放检测、退出和管理员撤销已实现。
- 客户端：DPAPI 保护会话文件，模块获得 `IPlatformContext`；当前只实现可信进程内上下文，跨进程 IPC 仍待开发。
- 模块：支持声明式 JSON 内容包的发布、下载、哈希核对、安全解包、展示及卸载；垃圾清理作为随平台编译分发的可信内置模块离线启用。其业务源码独立在 tools 下，平台只负责入口、安装状态、统一上下文和任务协调。通用原生程序运行器、原生模块独立下载/热更新、历史发布版本、更新回退及正式预装安装器尚未实现。
- 管理：独立管理用途会话、用户启停、会话撤销、内容模块发布/停用、审计列表已实现；角色管理界面待开发。
- 垃圾清理：已实现只读分类扫描、类目/文件选择、后果说明、排除目录、冻结计划、句柄校验删除及系统回收站确认。免费能力通过平台上下文离线判断；规则和文件路径留在本机。扫描后全部不选，临时文件快捷选择仍需用户确认。标准浏览器缓存适配规则与受控测试已实现，真实多版本验收未完成，详见模块 README。
- 验证：MySQL 8.4.11 下 41 项平台集成检查、35 项 API/启动集成检查通过，另有垃圾清理受控测试和真实目录只读扫描；实际多系统、安装器和生产部署验收待完成。

## 1. 已确认约束

- 根目录承载平台，`tools/<module-id>/` 存放各子应用的源码、资源、规则、测试和构建配置。
- 桌面平台使用 C# + WPF，兼容 Windows 10/11；模块按具体能力选择技术。
- 首版建设平台统一注册登录、服务端 API、管理后台和数据库。
- 所有模块的身份认证与权益校验统一依赖平台账号，不建立独立用户体系。
- 平台允许游客进入，垃圾清理全部免费、免登录、可离线使用。
- 首版不接入 AI；后续模块可以提供本地功能与可选联网增强。

## 2. 职责与数据流

```text
桌面平台（导航、安装、账号会话、统一授权客户端）
  ├─ 可信进程内模块接口（跨进程 IPC 待实现）
  │    ├─ tools/garbage-cleaner
  │    └─ 后续工具模块
  └─ HTTPS → 平台 API → 平台数据库

管理后台 → 受保护的管理 API → 平台数据库
```

桌面平台管理账号会话和模块生命周期，为模块提供当前用户的最小必要上下文、登录入口及能力授权结果。模块负责具体任务、界面、业务规则及本地操作。

服务端是用户身份、角色和未来付费权益的可信来源，所有需要登录的服务端操作必须验证凭证和对象权限。管理后台与桌面平台共用身份基础设施，但管理员角色、接口权限和会话用途独立控制。

客户端和子应用不直接连接平台数据库；数据库凭据、签名私钥及管理秘密只存服务端。文件扫描、清理计划和路径明细默认留在本机，不因为接入账号而自动上传。

## 3. 身份与授权是两个层次

身份回答当前是否登录、对应哪个平台用户；授权回答该用户或游客是否允许使用某个模块的具体能力。登录成功不自动获得全部付费能力。

平台用户只有一个稳定 User ID。需要存储用户业务数据的模块使用该 ID 关联记录，不复制密码、刷新令牌或建立可独立登录的用户表。

| 能力政策 | 身份要求 | 联网要求 | 判断来源 |
| --- | --- | --- | --- |
| 免费本地，例如垃圾清理 | 游客即可 | 不需要 | 受信任模块描述与本地固定政策 |
| 需登录的云服务 | 平台账号 | 需要 | 服务端会话与权限校验 |
| 未来付费在线功能 | 平台账号及对应权益 | 需要 | 服务端权益校验 |
| 未来付费离线功能 | 已激活的平台账号及有效离线凭证 | 凭证有效期内不需要 | 平台校验服务端签名凭证 |

统一授权接口允许明确的游客结果，不要求免费模块为获得允许结果而先联网。联网下载公开免费模块也不应仅为下载而强制注册。

## 4. 模块接入契约

模块清单至少描述：模块 ID、名称、版本、入口、平台协议版本、运行依赖、支持系统、能力列表、各能力的身份与联网要求。清单随可信模块包发布，影响收费的权益以服务端为准。

平台侧接口的建议职责如下，具体命名在实现时确定：

- `GetUserContext`：返回游客或已登录状态、平台 User ID 和确实需要的展示资料，不返回凭据。
- `RequestSignIn`：请求平台展示统一登录界面，不由模块收集密码。
- `CheckCapability(moduleId, capabilityId)`：返回允许/拒绝、原因和适用有效期。
- `UserContextChanged`：在登录、退出、换号或会话失效时通知模块更新界面和缓存。
- `RequestPlatformOperation`：在允许范围内代理模块需要的服务端请求。

进程内模块和独立进程模块使用同一套逻辑契约，不要求技术实现一致。本地 IPC 必须识别真实调用方，将模块 ID 与平台启动的实例绑定，不信任调用参数里自报的模块 ID，也不监听无保护的公共控制端口。

优先由平台代理账号相关请求；如果某模块确需直接调用服务端，只提供短期、限定接收方和能力范围的模块凭证，服务端再次校验。平台刷新凭证及管理员凭据不得提供给模块。

客户端检查负责使用体验，服务端授权负责保护云端资源和付费服务。对已下载到用户设备上的离线代码，不承诺本地校验能够绝对防破解。

## 5. 会话与离线行为

- 采用成熟身份组件处理密码哈希、验证与找回，不自行设计密码协议。
- 平台负责短期访问凭证、刷新轮换、退出和撤销；本地秘密通过 Windows 凭据保护能力保存。
- 退出或换号时清除旧用户会话与账号关联权益缓存，并通知已打开模块。
- 后台不可用或登录失效时，平台和免费本地模块继续运行；不将断网等同于账号被撤销。
- 未来离线付费能力使用服务端签名凭证，包含用户、模块/能力、设备关联、签发时间、有效期及版本；客户端只有验证公钥。
- 离线凭证的设备数、有效期、时钟异常及退款撤销窗口在收费前明确，不在本轮虚构政策。
- 权益失效时停止发起新的受限任务，已开始的文件操作按明确的安全结束流程处理。

## 6. 后端目录与数据

`backend/Api/` 承载普通用户和管理接口，`backend/Admin/` 承载管理界面，`backend/Database/` 保存结构说明、迁移及测试种子，`backend/tests/` 保存访问控制与集成测试。

首版逻辑模型：

| 模型 | 主要职责 |
| --- | --- |
| User / 身份组件凭据 | 平台唯一用户、登录标识、验证状态、账号状态 |
| AuthSession | 刷新会话、轮换、有效期、撤销及设备会话管理 |
| Role / Permission | 普通用户与管理员权限隔离 |
| Module / ModuleRelease | 模块介绍、能力、版本、兼容条件、下载和发布状态 |
| AuditLog | 用户管理、角色变更、版本发布等管理操作审计 |

后续付费阶段增加 Product、Order、PaymentEvent、Entitlement、DeviceActivation、LicenseGrant，统一关联平台 User ID 和模块/能力 ID。首版先定义授权接口和免费政策，不为尚未确定的收费方式硬编码订单规则。

`auth/continue` 按用户名查询：已有用户验证密码，新用户名以 Identity 创建用户并登录；新账号与首个会话在同一数据库事务内创建。用户名唯一索引阻止并发重名注册。API 另覆盖显式注册、登录、刷新、退出、当前用户，以及模块目录与版本查询；管理接口另行保护。用户只能访问自己的账号数据，普通用户不能调用管理能力。

账号使用用户名与 ASP.NET Core Identity；开发和生产后台统一使用 MySQL，连接凭据由服务端环境配置提供。桌面端和子应用不连接数据库。已有邮箱字段、历史待注册表和旧数据暂保留，不参与当前登录注册；当前不发送邮件。未来手机号必须经过验证码验证并唯一绑定到已有 User ID，换绑和找回均由平台处理，不影响模块的数据关联。

## 7. 实施与验收顺序

1. 创建平台与模块契约，先接入游客身份与免费授权政策。
2. 建立本地 API、数据库迁移、账号流程及管理权限基础。
3. 桌面平台接入统一登录会话，验证模块身份变化通知和账号隔离。
4. 交付垃圾清理只读扫描及预览，随后在受控环境中验证清理执行。
5. 完成模块安装与更新、管理后台模块发布和在线/离线分发流程。
6. 验证游客离线使用、多模块同一身份、退出换号、会话撤销、跨用户越权与管理权限隔离。

账号与后台纳入首版开发计划；支付、实际付费权益和 AI 在相应模块开发时接入。
